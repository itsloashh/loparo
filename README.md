# LOASH — gothic interactive artist platform

Next.js 16 · React 19 · TypeScript · Tailwind v4 · Motion · d3-geo · Supabase-ready · Vercel

```
DISCOVER → ART → MAP → LOCATION → AVAILABILITY → BOOK
```

## Run it

```bash
npm install
npm run dev          # http://localhost:3000 — runs on bundled sample data, no keys needed
npm run build        # production build
npm run preview:build  # static, server-less build of the same UI → dist-preview/ (shareable preview)
```

## What's where

```
src/
  app/                      Next routes (SEO metadata per page, sitemap, robots, API)
    page.tsx                Home / discovery
    work/ · work/[slug]/    Archive + deep-linkable pieces (static, OG images per piece)
    map/ · schedule/        "Where I'll be" + availability (linked through ?loc=)
    book/                   8-step guided inquiry (?ref= piece, ?stop=, ?date= prefill)
    about/
    admin/                  LOASH Admin — login, dashboard, work, schedule, inbox, profile
      actions.ts            Every admin write (auth-checked, then revalidates the public site)
    api/inquiries           Validates, stores in Supabase, uploads references, emails via Resend
    api/follow              "Follow Loash" city subscriptions
  components/               Views + UI. No component imports next/* except the adapter
    shell/NextProviders.tsx Next adapter for routing (the static preview uses a hash router)
    map/Atlas.tsx           Custom engraved vector map (swappable for Mapbox — same props)
  lib/
    types.ts                Domain model (mirrors the SQL)
    status.ts               THE availability language: labels, colours, glyph shapes
    selectors.ts            Next stop / next available / city status — all derived, never typed in
    data/sample.ts          Sample data (⚠ schedule = placeholders)
    data/supabase.ts        Live data mapper
    data/index.ts           getSnapshot(): Supabase if configured, else sample
supabase/
  migrations/0001_init.sql  Tables, enums, RLS, storage buckets
  seed.sql                  Same content as sample.ts (generated by scripts/gen-seed.ts)
scripts/                    Image crop/resize, logo cutout, geodata rewind, seed generator
public/work/                Portfolio renditions (480/828/1170 webp)
```

Every page reads one snapshot. Home's "Next stop / Next available", the map markers, the
schedule calendar and the booking flow's location/date steps are all computed from the same
`stops` + `availability` rows — change a status once and it changes everywhere.

## ⚠ Replace before launch

Anything marked **SAMPLE** / **PLACEHOLDER** in the UI:

All of these are editable in /admin (the dashboard lists what's left):
- [ ] **Schedule** — every seeded stop and day is invented sample data. Edit or delete them,
      and switch off "Mark as sample" on real ones.
- [ ] **Bio**, **portrait**, **FAQ answers** — Profile screen
- [ ] **Tattoo titles & descriptions** — drafted from what's visible in each photo only; confirm or rewrite
- [ ] **Custom** filter — tag pieces with the Custom style; the filter appears automatically
- [ ] **Logo** — the wordmark was cut from the logo card (`scripts/logo_cutout.py`). A
      transparent PNG/SVG export of the original would be sharper.

## Going live with Supabase

1. Supabase → SQL Editor → run, in order: `migrations/0001_init.sql`, `migrations/0002_admin.sql`, `seed.sql`.
2. Supabase → Authentication → Users → **Add user** (your email + a password, auto-confirm).
3. Vercel env vars (see `.env.example`): `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`,
   `SUPABASE_SERVICE_ROLE_KEY`, `NEXT_PUBLIC_SITE_URL`, and `ADMIN_EMAILS` = your email.
4. Optional: `RESEND_API_KEY` + `INQUIRY_NOTIFY_TO` → every inquiry emails you.
5. Push. Sign in at **/admin**.

## LOASH Admin (/admin)

Works on your phone. Every save goes live on the site immediately (no redeploy).

| Screen | What you can do |
|---|---|
| **Home** | New requests, next stop, open days in the next 30, pieces live, a "before launch" checklist |
| **Work** | Add a piece from your camera roll, edit title/styles/placement/description/alt text, ★ feature (home hero), hide/show, ▲▼ reorder, replace photo, delete |
| **Schedule** | Add/edit stops (city, type, dates, status, windows/spots, note), tap each day to set open/limited/full/closed/soon, add cities with "Find on map" |
| **Inbox** | Requests filtered by pipeline (New → Reviewing → Accepted → Deposit required → Confirmed → Completed / Declined), client reference photos, private notes, reply by email. Opening a new request marks it Reviewing. |
| **Profile** | Portrait, name, tagline, home city, bio, styles, "not offered", socials, FAQ |

**Photos:** resized in your browser to 480/828/1170px WebP and uploaded straight to Supabase
Storage — the server never handles the big original. An optional "trim black screenshot bars"
crop is on by default. Nothing else about the photo is changed.

**Security:** the proxy keeps the session fresh; the admin layout and *every* server action
re-check that you're in `ADMIN_EMAILS` or the `admins` table before reading or writing.

**Try it without a database:** `ADMIN_DEMO=1 npm run dev` → `/admin` shows the full UI on
sample data (saving is disabled). This never activates on Vercel.
